# تقرير فحص PRO 1.9.4 Reviewed Source

التاريخ: 2026-10-03

## المشكلة التي روجعت

الصورة المقدمة تظهر فشل تحليل يوتيوب، ثم سبع بطاقات فيديو بلا أبعاد أو حجم، وصوتيات MP3 بعدد صفر. مراجعة المصدر وجدت أن مسار الالتقاط الاحتياطي يقبل روابط videoplayback دون بيانات جودة، وأن اختيار MP3 كان يعتمد على العثور على صوت منفصل فقط. كما أن خيار QuickJS كان اسم runtime دون مسار الملف الأصلي. الصورة لا تحتوي سجل المحرك، لذلك لا يمكن تأكيد سبب فشل المحرك نفسه من الصورة وحدها.

## أخطاء إضافية مثبتة من مراجعة المصدر

اختيار استجابة يوتيوب كان يعتمد على عدد الصيغ دون استبعاد صور المعاينة، والتحليل الفاشل لم يكن يعاد بعد اكتمال تحديث المحرك. بعض تحديثات الالتقاط كانت تمسح سبب الفشل برسالة عامة. صححت هذه المسارات، وأضافت المراجعة إلغاء التحليل القديم وحداً زمنياً لكل محاولة. هذه نتائج مراجعة المصدر؛ سبب فشل الفيديو المحدد على الهاتف يحتاج سجل تشغيل فعلي، ولم يدّع الفحص تأكيده.

## فحوص نجحت

- node tests/capture.test.cjs: إرسال مباشر وتلقائي، تجميع تغييرات DOM، رصد MKV وTS، الحفاظ على Referer، Content-Range بحجم 4 GiB، تنظيف التنقل، وتمرير بيانات الجودة من script إلى الالتقاط.
- node tests/player_metadata.test.cjs: JSON اصطناعي للمشغّل يتضمن فيديو 360p بصوت، فيديو 1080p60 وصوت منفصل. تحقق الاختبار من الأبعاد والترميز والحجم الفعلي داخل البيانات، وعدم التعامل مع signatureCipher مشفر كرابط صالح، وعدم استعمال بيانات فيديو سابق.
- الاختبار المتكامل للإضافة: سبعة طلبات أجزاء للفيديو نفسه صارت جودة واحدة 1080p60، مع إبقاء مصدر الصوت وحجم الفيديو الكلي، واستبعاد UMP. هذه بيانات اختبار وليست استخراجاً حياً للفيديو في الصورة.
- python3 tests/format_rules_test.py: تشغيل دوال Java الفعلية للصيغ والبيانات، وفحص MKV وTS وAV1 و1080p60.
- python3 tests/download_plan_test.py: تشغيل كود خطة التنزيل الفعلي وفحص رابط الفيديو والصوت المنفصلين، وبيانات الفيديو بصوت لاستخراج MP3، وصوت منفصل، ورفض blob، ومسار QuickJS الأصلي. تم استبدال Context وYoutubeDLRequest ببدائل اختبار صغيرة؛ لم ينفذ yt-dlp أو FFmpeg على أندرويد.
- python3 tests/format_parser_test.py: تشغيل دالة parseFormats الكاملة من التطبيق ببدائل JSON للقراءة. التحقق من ترتيب 8K ثم 4K ثم 1080p، وصيغ AV1/MKV/TS، وربط الصوت المنفصل، وأربع جودات هدف MP3، واستخراج الصوت من فيديو بصوت، واستبعاد صور المعاينة والروابط الفارغة، وتفضيل الاستجابة ذات أعلى دقة.
- اختبارات الالتقاط الإضافية: استرجاع طلب شبكة مجهول التبويب بصفحة مصدر مطابقة، ومنع خلط تبويبين من الموقع نفسه، ومنع ظهور طلب صفحة سابقة وموارد الأداء القديمة بعد التنقل.
- تحليل بناء ملفات Java باستخدام JDK 17 نجح، وnode --check لجميع ملفات JavaScript نجح.
- صحة XML ومطابقة مراجع R.id مع معرفات التخطيط نجحت.

## حدود التحقق

أعيدت محاولة ./gradlew :app:assembleDebug. توقفت قبل تجميع أندرويد بسبب Network is unreachable عند تنزيل Gradle 8.11.1. لا يوجد APK جديد في هذه الحزمة.

لم يحصل بناء كامل أو تحقق من أنواع Android/GeckoView أو تجربة على هاتف أو استخراج حي من يوتيوب أو تنزيل/دمج فعلي بواسطة المحرك. الاختبارات المنطقية لا تعادل اختبار التطبيق على الهاتف، ولا تثبت أن كل فيديو متاح سيحمّل في ظروف الشبكة المختلفة.

تبقى القيمة الدقيقة للحجم متاحة عندما يرسلها المصدر أو بيانات المشغّل. القيمة المستنتجة من مدة وبتريت تظهر بعلامة ≈. لا يولد التطبيق حجماً أو دقة وهميين.
